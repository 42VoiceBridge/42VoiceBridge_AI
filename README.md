# 42VoiceBridge — AI 파트

구음장애(dysarthria) 화자용 음성 인식. 인식하고, 사용자가 **확인한 문장만** 음성으로 내보낸다.
개인 적응은 화자 본인의 소량 발화로 학습한 LoRA 어댑터로 한다.

이 리포는 **코드와 계약서만** 담는다. 2026-09-18 기준.

---

## 0. 이 리포에 데이터는 절대 들어가지 않는다

학습·평가에 쓰는 음성은 AI-Hub `구음장애 음성인식 데이터`(dataSetSn=608)다.
재배포 조건이 있다고 보고 있으므로 **음성, 라벨, 그리고 그로부터 파생된 모든 것**을 커밋하지 않는다.

`.gitignore`는 화이트리스트 방식이다. 기본이 `*`(전부 무시)이고 코드와 스펙만 되살린다.
블랙리스트는 새 파일이 생기면 조용히 새어나가지만, 화이트리스트는 막히는 쪽으로 실패한다.

들어가지 않는 것: `*.wav` · 라벨 JSON · `*_manifest.json` · `hyp*.json` · `results/` ·
`demo/samples/` · `demo/adapters/` · `b0*_16k/` · 지침 PDF · **`*.safetensors`**.

> 어댑터(`adapter_model.safetensors`)도 제외다. LoRA 가중치는 AI-Hub 음성으로 학습한
> **파생물**이지 코드가 아니다. 크기 문제가 아니라 출처 문제다.

데이터와 결과물은 팀 내부 폴더(`sw_challenge/`)에만 있다. 리포를 클론해도 바로 학습은 안 되고,
데이터 접근 권한을 따로 받아야 한다. 의도된 동작이다.

## 1. 지금까지 측정된 것

증거 태그: **[M]** 측정 · **[E]** 추정 · **[U]** 미검증 · **[pilot]** 파이프라인 확인용.

### 1.1 B0 — 적응 없는 기준선 [M]

AI-Hub 04 낭독 과제, 8개 화자군 31파일 3.32시간. faster-whisper, Colab T4.

| 집계 | small | large-v3 |
|---|---:|---:|
| 음절 CER (pooled) | 21.72% | **15.19%** |
| 자모 CER (pooled) | 15.98% | 12.54% |

화자군별 large-v3 자모 CER은 **0.020 ~ 0.520**으로 벌어진다.
**"범용 ASR은 구음장애에서 실패한다"는 전제는 측정으로 반증됐다** — 8개 군 중 4개가 0.020~0.041이다.
화자 간 격차(26배)가 과제 간 격차(3.9배)보다 6.7배 크다.

`file mean`을 "전체 CER"로 인용하지 말 것. pooled와 화자균등을 같이 쓴다.

### 1.2 B1 파일럿 — 첫 개인 적응 측정 [pilot]

whisper-small + LoRA(r32/α64, `q_proj,v_proj`), 화자별 1인 1어댑터, 14.18 MB.
등록/개발/평가 분할은 학습 전에 고정, 에폭 선택은 **개발 세트로만**.

| 실행 | 등록량 | test 자모 b0 → b1 | 상대 | 숫자제외 | 상대 |
|---|---:|---|---:|---|---:|
| KJW 전체 | 140문장 / 9.9분 | 0.0721 → **0.0472** | −34.5% | 0.0691 → 0.0455 | −34.2% |
| CYU 전체 | 374문장 / 31.3분 | 0.0852 → **0.0579** | −32.0% | 0.0787 → 0.0478 | −39.3% |
| KJW 30문장 | 30문장 / 2.3분 | 0.0721 → 0.0695 | −3.6% | 0.0691 → 0.0664 | −3.9% |
| CYU 30문장 | 30문장 / 2.5분 | 0.0852 → 0.0692 | −18.8% | 0.0787 → 0.0635 | −19.3% |

숫자제외 열은 **score-v2** 기준이다(2026-09-18 동결). 최초 공개본에는 score-v1 값
(KJW −33.0%, CYU **−42.3%**)이 실려 있었는데, 그 규칙은 제외 대상이 "그 실행에 어떤 시스템이
포함됐는가"에 따라 달라져서 전체 등록 조건과 30문장 조건을 **서로 다른 세그먼트 집합**에서
비교하고 있었다. score-v2는 참조와 짝 비교 시스템(`small_b0`/`small_b1`)만으로 제외를 정한다.
CYU의 정정값은 원래 값보다 **나쁘다.**

**이 숫자를 제품 주장으로 쓰면 안 되는 이유:**

1. **대상이 틀렸다.** KJW·CYU 둘 다 기준 오류가 낮은 화자다(large-v3 자모 0.056 / 0.052).
   도움이 절실한 고CER 화자(0.520, 0.168)에 대해 이 파일럿은 **아무것도 말하지 않는다.**
2. 세그먼트를 **아무도 들어보지 않았다.** 경계는 large-v3 단어 타임스탬프로 잡았고,
   앞뒤 2글자가 정확히 맞는 것만 채택했다 — 쉬운 구간 쪽으로 선택 편향이 있다.
3. 단일 시드, 등록과 **같은 과제·같은 녹음 세션**의 평가 세트. 과제·날짜·마이크가 바뀌면 모른다.

**제품에 직접 쓸 수 있는 한 줄은 정확도가 아니라 등록 부담이다.**
30문장(약 2.5분)이면 CYU는 −18.8%, KJW는 −3.6%(음절 기준으론 오히려 악화).
**30문장 등록은 전체 결과의 축소판이 아니다.**

## 2. 숫자를 인용할 때 반드시 같이 쓸 것

지금까지 실제로 물린 함정들이다. 문서에 숫자를 옮길 때 이 절을 먼저 읽는다.

| 함정 | 내용 |
|---|---|
| **폭주 출력** | `beam_size=5`에서 whisper-small이 `아, 그래요?`(4음절)를 `아` 200토큰으로 뱉었다. 그 **한 세그먼트가 20개짜리 분할 오류의 86%**를 만들어 CER을 0.160 → 0.928로 올렸다. 한글 반복은 정규화에서 안 지워지고 삽입 오류로 잡힌다. CPU/fp32에서 동일 재현 — GPU·fp16 문제가 아니다. **대응: 계약 D9으로 greedy 고정.** `summary.json`의 `runaway` 목록이 비었는지 확인하고 인용한다 |
| **숫자 표기** | 채점기가 참조·가설 양쪽에서 숫자를 지운다. 그런데 라벨의 숫자 표기가 **일관적이지 않다** (CYU: 아라비아 13개 + 한글 13개, KJW: 아라비아 0개). 숫자로 쓴 라벨은 숫자로 쓰는 기본 모델에 공짜 0.000을 주고, 풀어 쓰는 어댑터에 벌점을 준다. **숫자제외 변형을 같이 본다** |
| **지표·변형이 승자를 바꾼다** | 적응 small vs zero-shot large-v3는 8칸 중 6칸에서 small이 이기는데, **large가 이기는 2칸이 변형에 따라 달라진다.** 원시 test에선 CYU 음절(large 0.0751 < 0.0785), 숫자제외에선 KJW 음절(large 0.0662 < 0.0751). **"small+LoRA가 large-v3를 이긴다"고 쓸 수 있는 문장은 없다.** 쓸 수 있는 건 "이 두 저CER 화자에서 적응한 244M 모델이 zero-shot large-v3와 비등하다"까지다 |
| **참조는 의도 기준** | 구축 지침이 "화자 의도대로" 전사하게 되어 있다. 축약(`재밌었어요`)·존대 변형이 오류로 잡힌다. CER은 "발음을 얼마나 맞혔나"가 아니라 **"의도한 문장을 복원했나"**다 |
| **녹음 시간 ≠ 발화 시간** | 파일 길이는 녹음 슬롯이다. 37.9시간은 **녹음 시간**이고 실제 발화는 8~11시간 추정 [E] |

## 3. 돌리는 법

### 3.1 시연 서버

```bash
cd demo
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 server.py          # 첫 실행 시 openai/whisper-small 약 1 GB 내려받음
```

## 5. 계약 (백엔드 연동)

`docs/AI_BACKEND_CONTRACT_v1_EN.md`가 기준이다. v1에서 고정된 것 중 연동에 영향 있는 것:

- **D3** 서버는 **WAV PCM 16-bit 모노 16 kHz, 0.3~30초**만 받는다. 폰 포맷 변환(AAC/M4A/WebM)은
  백엔드가 실제 디코더로 한다
- **D4** `alternatives`는 항상 `[]`, `score`는 항상 `null`. 스키마에만 존재한다. **채워 넣지 않는다**
- **D5** **확인한 문장만** 합성한다. 확인 후 수정하면 확인이 무효가 된다
- **D6** 어댑터는 서버가 `user_id`로 고른다. 클라이언트가 지목할 수 없다
- **D8** 저장 동의와 학습 동의는 **별개 플래그, 둘 다 기본 false**
- **D9** 디코딩은 **greedy(`beam_size=1`)**. 2절의 폭주 항목 참조

## 6. 아직 안 된 것

- **고CER 화자 적응 파일럿.** §1.2가 답하지 못한 실제 질문이다. 세그먼트 청취 검수가 선행돼야 한다
- **청취 검수.** 지금까지 이 데이터의 오디오를 들어본 사람이 아무도 없다
- **정규화 규칙 동결.** 숫자 표기 두 관습을 모두 처리해야 한다 (2절)
- **온디바이스 추론.** 9/23 프로토타입은 서버 추론(D1)으로 결정됐다. 폰에서 측정하기 전까지
  **오프라인 동작을 주장하지 않는다**
- **여러 후보·신뢰도 표시.** UX 가설이지 검증된 안전장치가 아니다

## 7. 화면 문구 규칙

측정에서 나온 제약이다. 바꾸기 전에 근거를 확인할 것.

- 약한 자모 화면은 **"모델이 자주 놓칩니다"**로 쓴다. **"발음이 부정확합니다"는 금지.**
  참조가 의도 기준이라 화자의 실제 발음 오류율은 복원되지 않는다
- 자모 분해는 **표기 기준**이지 음성 기준이 아니다. G2P 파이프라인이 생기기 전까지
  "자모 단위 모델 오류 통계"라고 부른다
- 사용자에게 **더 또박또박 말하라고 요구하는 표현**을 쓰지 않는다
- 확인하지 않은 스트리밍 출력은 **절대 소리로 내보내지 않는다**
