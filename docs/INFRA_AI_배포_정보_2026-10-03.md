# 인프라에 전달하는 AI 서버 정보

2026-10-03, AI 파트. `deploy-step.md`와 ADR 0005를 읽고 쓴 문서다.

## 1. CI에서 Infra 호출 — 이벤트 이름 확인 필요

`deploy-step.md` 4번에 맞춰 AI CI가 이미지 발행 성공 후 Infra로 `repository_dispatch`를 보낸다.
토큰은 `INFRA_DISPATCH_TOKEN`을 쓴다.

```json
{
  "event_type": "deploy-ai",
  "client_payload": {
    "ref": "refs/heads/main",
    "sha": "<AI 커밋 40자>",
    "image": "ghcr.io/42voicebridge/42voicebridge_ai:sha-<커밋>"
  }
}
```

**Infra 쪽에 `deploy-ai` 타입을 추가해 주셔야 동작한다.** 지금 `cd-preflight.yml`은

```yaml
repository_dispatch:
  types: [deploy-backend]
```

만 선언하고, 이어지는 단계에서 SHA를 **BE 커밋으로 검증**한다. AI가 `deploy-backend`를 보내면
Infra가 AI 커밋을 BE 커밋으로 취급한다. 그래서 `deploy-ai`로 보낸다. 타입이 없는 동안에는
API가 요청만 받고 아무 워크플로도 돌지 않는다 — 조용히 잘못 배포되는 것보다 낫다고 봤다.

`image`는 Infra가 SHA로 태그를 다시 조립하지 않도록 넣었다. 필요 없으면 무시해도 된다.

## 2. 메모리 실측

ADR 0005의 Accepted 조건 2번에 필요한 숫자다. 컨테이너에 4GB 제한을 걸고 측정했다.

| 시점 | 메모리 |
|---|---|
| 모델 적재 후 대기 | **517 MiB** |
| 전사 3건 후 | **1.67 GiB** |

- 이미지 1.61GB, CPU 전용, 포트 8000, 비루트 uid 10001
- 첫 요청 3.9초, 이후 0.65초 (전사 1건)
- **3건으로 측정했으므로 상한이 아니다.** 오래 돌렸을 때 어디서 멈추는지는 모른다.
  PyTorch가 메모리를 재사용하므로 계속 늘지는 않을 것으로 보지만 확인 안 했다.
- arm64 컨테이너 측정이다. EC2는 amd64라 숫자가 조금 다를 수 있다.

`m5.large` 8GiB를 BE JVM과 나눠 쓰는 판단은 이 숫자로 해주시면 된다.

## 3. ADR 0005 정정 요청 — CPU 학습

ADR에 이렇게 적혀 있다.

> `ALLOW_CPU_TRAIN=1`은 CPU 학습을 허용하는 짧은 테스트용 설정이며 운영 성능은 검증되지 않았다

**코드만 보면 맞는 읽기다.** 플래그 이름이 그렇게 읽힌다. 그런데 측정했다.

| | GPU (H100) | CPU |
|---|---|---|
| 학습 시간 | 18초 | **1055초 (17.6분)** |
| 기준 CER | 0.5030 | 0.5030 (동일) |
| 선택된 에폭 | 1 | 1 (동일) |
| 어댑터 크기 | 14,176,064 바이트 | **바이트 단위 동일** |
| 학습 후 CER | 0.3905 | 0.3787 |

CPU가 58.6배 느리지만 **품질은 같다.** 마지막 줄 차이는 학습 비결정성이다.

그래서 CPU 학습은 "짧은 테스트용"보다는 **느리지만 쓸 수 있는 경로**다. 사용자에게는
"약 20분 뒤 개인 모델이 준비됩니다"가 되고, 어차피 요청-응답으로 할 수 없어서 비동기다.
GPU를 계획에서 빼는 결정은 이 숫자로 보면 문제없다.

다만 **이 측정은 H100 서버의 CPU에서 한 것이고 `m5.large`가 아니다.** 2 vCPU에서는 더 걸린다.
학습은 BE와 같은 EC2에서 돌리면 추론 응답시간에 영향을 줄 수 있다.

## 4. GHCR 패키지 접근

`deploy-step.md` 2번의 "GHCR 패키지 공개 여부를 확인한다" 항목.

인증 없이 패키지 API를 호출해보니 `Requires authentication`이 돌아왔다. **비공개로 보인다.**
EC2에서 받으려면 읽기 자격증명이 필요하다. 저희 쪽에서 공개로 바꾸는 판단은 하지 않았다 —
공개로 바꾸면 이미지 내용이 누구나 받을 수 있게 되므로 팀 결정이 맞다고 봤다.

## 5. AI 주소

포트 8000이다. BE 컨테이너 안의 `127.0.0.1`은 AI 주소가 아니라는 점은 문서에 이미 적혀 있다.
같은 EC2의 별도 컨테이너로 올리면 Docker 네트워크의 서비스 이름을 쓰면 된다.

**트래픽 보내기 전에 `GET /v1/health`가 응답할 때까지 기다려야 한다.** 모델 적재에 수 초
걸린다. Dockerfile에 `HEALTHCHECK`를 일부러 넣지 않았다 — 적재 중에 재시작 루프가 돌면
체크가 없는 것보다 나쁘다.

## 6. 마운트 3개

이미지에 들어 있지 않다. AI-Hub 데이터로 만든 것이라 발행 이미지에 넣으면 재배포가 된다.

| 경로 | 내용 | 없으면 |
|---|---|---|
| `/data/hf` | 모델 가중치 캐시 | 첫 기동에 약 1GB 다운로드 |
| `/data/adapters` | 개인화 LoRA | 기본 모델로만 동작 (정상 상태) |
| `/data/script_pool.json` | 읽을 문장 목록 | 문장 추천·등록 API가 503 |

`/data/adapters`와 `/data/enroll`은 **컨테이너보다 오래 살아야 한다.** 재배포 때 날아가면
사용자 개인화가 사라진다.
